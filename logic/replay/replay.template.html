Neurosymbolic logic solver

A small language model translates each puzzle into formal rules. A solver (Z3) does the reasoning and proves every answer choice right or wrong.

    Reading the results
    
    
      
      
    • Where the pipeline wins: it beats gpt-oss-120b (low) and gpt-oss-20b (low), both by a significant margin. It is statistically tied with gemma4-31b, with thinking on or off, at 2.7–20× lower cost per correct answer.
      • 
      
    • Where bigger models win: with reasoning on high, gpt-oss-120b, nemotron-3-super and nemotron-3-nano reach 97–99%. That takes 6k–21k output tokens per problem (vs. 770) and costs 24–32× more per correct answer.
      • 
      
    • Active parameters: gpt-oss-120b is a mixture-of-experts model that runs about 5.1B parameters per token, close to the pipeline's 4.6B total. The model doing the hard part of the pipeline, extraction, is 0.6B.
      • 
      
    • Tokens vs. cost: the pipeline uses more tokens than gpt-oss-120b (low), 1,409 vs. 807 per problem, but those tokens run on much smaller models, so they cost less. Token counts are only roughly comparable across models, since each uses a different tokenizer.
      • 
    
    

    
    Caveats
    
    
      
      
    • Chance level: 73 of the 101 puzzles have two answer choices, so random guessing scores about 45%.
      • 
      
    • Test set: the puzzles come from the same generator as the training data, so they are in-distribution for the fine-tuned model, but none of the 101 were in its training data. The baseline models answer zero-shot.
      • 
      
    • Pipeline cost is estimated: the pipeline runs locally, so it is priced at public API rates for its base models (Qwen3-0.6B on Fireworks, Qwen3-4B on Nebius). Baselines use Ollama Cloud list prices.
      • 
    
    

    
    Why these puzzles
    
    
    The three puzzle types are modeled on the logic games in the LSAT's Analytical Reasoning section, which tests deduction from a fixed set of rules:
    
    
      
      
    • Ordering: place people in positions from clues like "Amy is before Olga." This is the LSAT's sequencing game.
      • 
      
    • Grouping: assign people to groups under inclusion and exclusion rules. This is the LSAT's other main game type.
      • 
      
    • Knights and knaves: truth-tellers and liars whose statements constrain each other. This classic puzzle adds conditional and self-referential logic.
      • 
    
    
    
    74 of the 101 test puzzles combine two or three types. Each puzzle has one provably correct answer, and the answer choices take the LSAT's form ("must be true", "could be false"). The puzzles take careful multi-step reasoning for an LLM, but Z3 can check every answer exactly.
    

    
    How it works
    
    
    Puzzle text→Classifier (Qwen3-4B) picks puzzle types→JSON schema for just those types→Fine-tuned Qwen3-0.6B extracts constraints→Z3 tests each answer choice→Answer + explanation
    
    
    The language model only translates the puzzle into structured constraints, and Z3 does the reasoning. Constrained decoding against a schema narrowed to the puzzle's types limits what the model can get wrong, which is what makes 0.6B enough.
    

    
    RAG pilot: retrieved examples for the base 0.6B
    
    
    A separate experiment: can the base Qwen3-0.6B, without fine-tuning, extract better if its prompt shows worked examples that look like the puzzle? For each test puzzle, the 3 most similar of the 915 training puzzles are put in the extraction prompt, each as puzzle text plus its gold JSON. Retrieval only ever searches the training set.
    
    
    
      
      
    • Accuracy: 16.8% → 26.7% (17 → 27 of 101). Only RAG got 17 puzzles right and only no-RAG got 7 (exact McNemar p = 0.064): a strong trend, just short of significant.
      • 
      
    • Fewer contradictions: extractions that Z3 found self-contradictory fell from 30 to 19.
      • 
      
    • Gains are mostly on single-type puzzles: 6 → 13 of 27. Puzzles that mix two or three types barely moved (11 → 14 of 74).
      • 
      
    • Cost: about 2.8× the input tokens (1,218 → 3,361) and 2× the time per puzzle (7.7 s → 15.4 s).
      • 
      
    • For scale: the fine-tuned 0.6B in the main pipeline scores 91.1%.
      • 
    
    
    
    Caveat: the test puzzles come from the same generator as the training puzzles, so a close match always exists. This shows RAG helps on puzzles like the training set. It doesn't yet show it helps on puzzles written in other words.
